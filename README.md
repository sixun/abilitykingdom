# 어빌리티킹덤 웹 프로토타입 (v0.1)

기획서(2026-10-11)와 채택 시안(formation-selected.png)을 기준으로 만든 **메뉴·편성·성장 흐름 검증용 프로토타입**입니다.
전투·확률·가격·계정·서버는 확정되지 않았으므로 임시 규칙과 샘플 데이터로만 연결했습니다.

## 실행법

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # dist/ 생성 (정적 호스팅 가능, 상대 경로)
npm run test:e2e     # dev 서버 실행 중에 브라우저 자동 검증 (Playwright)
```

- 개발용 바로가기: `?screen=formation`, `?screen=recruit` 처럼 화면 이름을 붙이면 로비 위에 그 화면을 바로 엽니다.
- 진행 데이터는 브라우저 localStorage(`ability-kingdom.save.v1`)에 저장됩니다. 설정 > 로컬 데이터 초기화로 처음 상태로 돌립니다.
- 설정 > 개발·검증 > 요청 실패 시뮬레이션: 요청 일부를 실패시키거나 "처리 후 응답 유실"을 흉내 냅니다. 재시도해도 중복 차감·지급이 없는지 확인용입니다.

## 기술 선택 (임시)

기존 저장소·엔진·코드가 없어서, 화면 흐름과 상태 저장을 바로 검증할 수 있는 웹(React 18 + TypeScript + Vite)으로 시작했습니다. 엔진은 기획서대로 **미정**입니다.

| 후보 | 맞는 경우 |
| - | - |
| Unity (2D/URP + Spine 또는 Live2D) | 실시간·액션 전투, 3D 카메라 연출, 모바일 스토어 출시가 목표일 때 |
| 웹 유지 (React/Pixi + Capacitor 래핑) | 메뉴·수집 중심, 자동/턴제 전투, 빠른 반복이 중요할 때 |

어느 쪽이든 `src/game/`(데이터 타입·규칙·서비스 인터페이스)의 책임 분리를 그대로 옮길 수 있게 만들었습니다.

## 구조

```
src/game/types.ts         CharacterDefinition, OwnedCharacter, TeamPreset, LobbyPreference, Wallet, RecruitmentTransaction …(기획서 14항)
src/game/config.ts        팀 인원(4), 프리셋 수(3), 중복 배치, 최소 출전 인원 등 임시 기준값
src/game/rules.ts         전투력·레벨업 비용·자동 편성 기준 (임시 공식, UI에 하드코딩하지 않음)
src/game/service.ts       GameService 인터페이스 (서버 구현으로 교체할 경계)
src/game/localService.ts  로컬 구현: requestId 기반 중복 방지, 원자적 차감·지급, 기간·한도 검증
src/game/data/            샘플 캐릭터·아이템·배너·상품·콘텐츠·운영 데이터
src/screens/              화면별 구성 (편성, 로비, 영입, 상점, 가방, 캐릭터, 여섯 콘텐츠, 출전 준비, 테스트 전투, 운영 메뉴)
src/app/                  화면 스택·전환, 합성 사운드, 오프닝 영상 로더
public/assets/            배경·캐릭터 분리 에셋, 오프닝 영상
tests/                    자동 검증 스크립트
```

## 구현한 동작

**흐름**: 초기 로딩(영상 버퍼링) → 오프닝 영상(15초) → 영상 속 타이틀(13초~)에서 입력 대기 → 입력 시 로비. 영상이 끝나도 자동 진입하지 않고 마지막 장면을 유지합니다. 다시 실행하면 SKIP, 연출 감소 설정 시 타이틀부터 재생, 영상 실패 시 정적 타이틀로 대체합니다. 웹 정책상 소리를 켜려면 초기 로딩에서 한 번 탭(TAP TO START)이 필요합니다.

**편성(채택 시안)**: 왼쪽 패널(뒤로가기·제목·팀 01~03·이름 수정·팀 전투력), 플랫폼 위 4인, 바닥 슬롯 01~04, 하단 아이보리 보유 캐릭터 바, 노란 저장 버튼.
- 슬롯 선택 → 하단에서 캐릭터 선택 시 교체 / 이미 팀에 있으면 위치 교환 / 중복 배치 금지(설정값)
- 리더 배지(노랑)와 선택 상태(청록) 분리, 리더 지정·빼기, 빈 슬롯은 번호와 추가 버튼
- 상세(i)와 교체 동작 분리, 저장 전 변경 표시, 저장 안 하고 팀 전환·뒤로가기 시 저장/변경 취소/계속 편집
- 초기화 = 마지막 저장 상태로 되돌림, 자동 편성 = 임시 규칙(전투력순) 안내
- 교체 연출: 기존 인물 퇴장 + 새 인물 진입, 연타 시 이전 연출 정리(최종 선택과 화면 인물 일치)
- 캐릭터마다 주기·위상이 다른 대기 동작, 선택 시 반응 + 바닥 표식 반응

**로비**: 대표 캐릭터 1명(팀 리더와 별도 저장), 첫 진입·대표 변경 시 캐릭터별 등장 연출(참격·방벽·충격파·치유·중력 등), 메뉴 복귀 시 짧은 복귀 연출, UI 숨김 감상 모드, 6개 콘텐츠 진입, 관리 메뉴(캐릭터·편성·가방·영입·상점), 우편·미션·공지·설정·출석·이벤트·프로필.

**캐릭터**: 목록(역할 필터·보유만·정렬), 상세 4탭(기본 정보=상반신 / 스킬=동작 포즈 / 장비=전신 / 성장=중간 구도로 카메라 전환), 레벨업(+1/+5/+10, 전후 수치·필요 재료·부족 표시), 장비 장착·해제, 로비 대표로 설정.

**영입**: 한정·상시, 배너 목록, 픽업 소개, 기간, 1회·10회, 상세 정보·확률 정보(샘플 표기)·기록·교환소 연결, 영입 포인트. 결과: 개별 등장 → 전체 결과 → 확인/다시 영입. 스킵·재열람은 같은 거래를 보여주기만 합니다.

**상점·가방**: 추천·패키지·재화·교환소, 구성·가격·구매 한도·기간 표시, 테스트 재화 구매. 실결제 상품은 "결제 미연동"으로 비활성. 가방은 장비·소모품·재료와 실제 지원 동작(사용·잠금·장착 위치 이동)만 노출.

**여섯 콘텐츠**: 스토리(노선·역 형태 스테이지), 도시 탐색(가상 구역 지도·사건), 현상수배(골목 게시판), 훈련(종류·난이도), 아레나(등급·상대·방어 편성·전적), 레이드(보스·난이도). 모두 공통 출전 준비(팀 선택·편성 변경·적 정보·필요 행동력·보상) → 테스트 전투(체력·스킬·목표·일시정지·배속) → 결과(승패·보상·재도전·로비 복귀)로 연결됩니다.

## 검증 결과 (2026-10-11, Chromium headless 1280×720)

`npm run test:e2e` 두 스크립트, 총 90여 항목 통과 / 실패 0 / 콘솔 오류 0.

- 오프닝 영상 재생, 13초 이후에만 입력 대기, 입력 없이 자동 진입하지 않음, 오프닝 화면에 한글 없음, 영상 차단 시 정적 타이틀 대체
- 로비 → 편성 → 교체 → 저장 → 로비 → 재진입 시 저장 상태 표시
- 팀 내 캐릭터 선택 시 위치 교환, 저장 전 이탈 팝업, 팀 이름·리더 저장, 팀별 독립 저장, 빈 슬롯, 초기화, 자동 편성
- 같은 슬롯 연타 5회 후 최종 선택·화면 인물·저장 결과 일치, 퇴장 잔상 없음
- 새로고침 후 저장 상태 복원
- 로비 대표 변경이 팀 리더를 바꾸지 않음
- 로비의 6개 콘텐츠·관리 메뉴·보조 메뉴 18개 링크 모두 진입·복귀
- 10회 영입 1회 차감, 스킵해도 재실행 없음, 기록 재열람 결과 동일, 1회 영입 연타 시 1회만 차감
- 요청 실패·응답 유실 시뮬레이션에서 재시도해도 상점 구매 1회만 차감·지급
- 우편 모두 받기 후 알림 점 해제·재수령 불가, 미션·출석 1회 수령
- 6개 콘텐츠 출전 준비 진입, 테스트 전투 → 결과 → 로비 복귀, 행동력 차감·보상 1회 지급

화면비 확인: 1920×1080, 1280×720, 915×412(휴대폰 가로), 1024×768(4:3), 390×844(세로 → 가로 스테이지를 회전해 표시).

아직 측정하지 않은 것: 실제 모바일 기기 성능(60fps는 목표값), iOS Safari 실기기 오디오·영상 재생, 노치 기기 안전 영역 실측.

## 임시 에셋

| 에셋 | 상태 |
| - | - |
| 캐릭터 8명 × 전신(편성·상세) + 동작 포즈(로비 등장·스킬·영입) + 초상 | 시안을 스타일 참조로 AI 생성(Creative Claw, nano-banana-2) 후 배경 제거한 **정적 이미지**. 리깅·프레임 애니메이션 아님 |
| 배경 10종(플랫폼·로비·영입·상점·지도·스토리·수배·훈련·아레나·레이드) | AI 생성 임시 배경. 간판 문자는 비워 두도록 생성 |
| 오프닝 영상 | 사용자 제공 영상(HEVC 41MB)을 H.264 MP4(1080p 8.5MB, 720p 4.4MB)·VP9 WebM(1080p 6.2MB)으로 재인코딩 |
| 사운드 | BGM·효과음 모두 코드 합성 임시음. 음성 에셋 없음 |
| 글꼴 | Black Han Sans(앱 사용 한글만 서브셋, `npm run fonts`로 재생성), Anton, 본문은 Noto Sans KR(Google Fonts)·시스템 글꼴 |

캐릭터 이름·레벨·전투력·재화·지명·대사는 모두 샘플입니다. 캐릭터 "움직임"은 CSS로 정적 이미지를 흔들고 교차하는 수준이며, 시선 돌리기·자세 변경 같은 실제 포즈 전환은 리깅 에셋이 필요합니다.

## 미구현 · 확정 필요 범위

- **전투**: 테스트 전투만 있음(실시간·자동·턴제, 조작, 팀 교대, 카메라 미정). 실제 전투는 규칙 확정 후 별도 산정
- **서버·계정·결제**: 전부 로컬 저장. 재화·영입·구매·보상은 운영 전 서버 권한으로 이전 필요(인터페이스는 분리됨). 실결제·영수증 검증 없음
- **확률·천장·중복 전환·가격·성장 공식**: 샘플 값. 중복 획득은 기록만 함
- **최종 로비·영입·상점 디자인**: 로비는 가로 소파 후보 기준, 영입은 '스카우트 방송' 스킨 + '플랫폼' 스킨만 구현(4개 후보 중 미선택). 세로 로비는 미구현
- **아레나 매칭·시즌, 레이드 협동, 도시 탐색 맵 생성·이동, 스토리 분량·해금**: 고정 샘플
- **일일 초기화 시각, 행동력 자연 회복, 캐릭터 대화(메시지), 친구·길드·채팅**: 없음
- **코스튬, 돌파·각성·호감도**: 후보 시스템이라 넣지 않음
