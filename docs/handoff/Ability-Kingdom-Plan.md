# 어빌리티킹덤 앱 제작 기획서

작성 기준: 2026년 10월 11일. 클로드에게 전달할 어빌리티킹덤 앱 제작 기획이다. 현대 한국 도시를 배경으로 능력자를 수집하고 팀을 구성하는 게임이며, 캐릭터의 개성과 빠른 메뉴 연출이 제품의 핵심이다. 편성 화면은 사용자가 선택한 가로형 지하철 플랫폼 시안을 기준으로 한다.

## 2 제품과 시각 디자인

사용자가 로비에서 자신의 캐릭터를 보고, 팀을 편성하고, 도시의 사건에 참여하며, 보상으로 캐릭터를 성장시키는 흐름을 만든다. 상세 전투 규칙을 제외한 메뉴와 성장 흐름은 실제로 조작할 수 있어야 한다.

니케·명일방주·블루 아카이브는 정보 배치와 메뉴 기능의 참고다. 젠레스 존 제로와 페르소나 5는 캐릭터 포즈, 카메라, 타이포그래피, 패널의 움직임을 결합하는 연출 참고다. 기존 게임의 캐릭터·로고·음악·UI 에셋을 그대로 가져오지 않는다.

화면마다 다른 장소와 구도를 사용한다. 로비는 개인의 공간, 편성은 동료가 모이는 플랫폼, 영입은 픽업 캐릭터를 소개하는 장면, 상점은 상품을 비교하는 공간으로 구분한다. 큰 캐릭터 한 장 위에 버튼만 바꾸는 방식으로 모든 메뉴를 반복하지 않는다.

현대적인 스트리트 의상과 일상 공간에 능력자의 비일상적인 행동이 섞인다. 실제 지명은 분위기 참고이며 가상의 도시 구역명으로 바꿀 수 있다. 시안의 노선 순서와 역간 연결은 실제 철도 정보로 간주하지 않는다.

기본 그래픽은 차콜·아이보리 바탕에 화면별 강조색을 사용한다. 편성은 청록색 선택 상태와 노란색 저장 버튼을 우선한다. 과감한 사선과 큰 제목을 쓰되, 본문·레벨·비용·버튼은 읽기 쉽게 정렬한다. 장식 문장과 캐치프레이즈는 최소화한다.

## 3 참조 이미지와 적용 우선순위

1. formation-selected.png: 사용자가 이번에 선택한 최우선 편성 시안. 배치, 공간, 인물 크기, 색상 관계를 우선 보존한다.
2. lobby-landscape.jpeg: 소파에 캐릭터 한 명이 누워 있는 가로 로비 방향 후보.
3. lobby-portrait.jpeg: 지하철 공간의 캐릭터 한 명을 중심으로 한 세로 로비 방향 후보.

편성 시안 선택만 확정되었다. 두 로비 이미지는 기존 방향 참고이며 최신의 명시적 최종 선택은 없다. 이미지에 적힌 캐릭터 이름·레벨·전투력·재화·역명·자잘한 문구는 확정 데이터가 아니다. 이미지의 텍스트 오류를 그대로 재현하지 않는다.

이미지 한 장을 전체 화면 배경으로 깔고 그 위에 투명 버튼만 얹는 것으로 구현을 끝내지 않는다. 배경, 캐릭터별 이미지, 전경, 효과, 텍스트와 조작 UI를 분리해야 캐릭터 교체와 애니메이션이 가능하다. 원본 레이어가 없는 시안은 시각 목표이며 제작용 분리 에셋은 추가로 필요하다.

## 4 앱 흐름과 메뉴 구조

첫 진입은 초기 로딩 → 오프닝 → 타이틀 대기 → 사용자 입력 → 로비 순서다. 로그인과 계정 복구는 계정 시스템을 결정한 뒤 흐름에 결합한다.

로비에서는 스토리·도시 탐색·현상수배·훈련·아레나·레이드 여섯 콘텐츠로 진입한다. 캐릭터·편성·가방·영입·상점은 별도의 관리 메뉴다. 관리 메뉴를 6개 플레이 콘텐츠 안에 억지로 포함하지 않는다.

공통 상단에는 돌아가기, 화면명, 필요한 재화만 표시한다. 재화가 필요 없는 화면에 구매 UI를 과도하게 넣지 않는다. 공통 보조 메뉴로 우편함, 공지, 이벤트, 미션, 설정을 제공한다. 친구·길드·실시간 채팅은 현재 확정 범위가 아니다.

로비 캐릭터와 팀 리더는 별도 저장한다. 로비에 전시한 캐릭터를 바꿨다고 전투 편성이 바뀌지 않으며, 편성을 수정했다고 로비 캐릭터가 자동으로 바뀌지 않는다.

## 5 오프닝과 타이틀

길이는 약 15초를 기준으로 한다. 가장 중요한 요구는 속도감이며, 장면 종류도 충분히 다양해야 한다. 단순 슬로모션과 정지 포즈를 길게 연결하지 않는다. 도시, 이동, 능력 발현, 그래픽 컷을 리듬 있게 결합한다.

기존 CITY VELOCITY와 GRAPHIC OVERDRIVE는 제작한 후보이며, 최종 오프닝 선택은 아직 미정이다. 기존 2개 영상을 자동으로 이어붙이지 않는다. 사용자가 제공한 젠존제 영상 2개는 메뉴 애니메이션 참고이며 오프닝 콘티로 오해하지 않는다.

타이틀 종료 부분에는 ABILITY KINGDOM과 PRESS ANY BUTTON을 배치한다. 모바일은 화면 터치, PC는 일반 키·마우스, 컨트롤러 지원 시 확인 입력으로 진입한다. 영상이 끝났다고 입력 없이 자동으로 로비에 들어가지 않는다.

권장 동작은 마지막 장면을 짧은 루프 또는 정지 타이틀로 유지하는 방식이다. 반복 실행 시 스킵, 영상 재생 실패 시 정적 타이틀 대체, 오디오 설정 존중을 구현한다. 영상 후반의 타이틀을 앱 UI로 올리면 다양한 비율에서 글자 잘림을 줄일 수 있다.

## 6 로비

대표 캐릭터 1명이 화면의 중심이다. 사용자가 보유 캐릭터 중 선택하며, 캐릭터마다 등장 장면과 대기 동작을 가진다. 동일한 등장 영상을 모든 캐릭터에 돌려 쓰지 않는다.

지하철 로비 후보는 플랫폼·열차 공간, 소파 로비 후보는 일상의 실내 공간을 활용한다. 어느 방향이든 중요한 버튼이 얼굴을 가리지 않도록 한다. 콘텐츠 버튼은 장식 배너와 구분하고 모든 콘텐츠가 찾기 쉬워야 한다.

로비 재진입마다 긴 등장 장면을 강제하지 않는다. 권장 초기값은 첫 진입과 대표 캐릭터 변경 시 등장 연출, 일반 메뉴 복귀 시 짧은 복귀 연출이다. 정확한 재생 정책은 조정 가능하게 한다.

로비 캐릭터 선택, UI 숨김 감상 모드, 우편 보상 수령, 미션 진행 확인, 이벤트 이동의 기본 동작을 연결한다. 원 시안의 중복 이벤트 버튼과 일관되지 않은 소환·모집 명칭은 정리한다.

## 7 채택된 지하철 플랫폼 편성창

### 화면 배치

가로형 16대9 시안을 기준으로 구성한다. 왼쪽 약 18퍼센트에는 어두운 세로 패널, 중앙에는 4명의 팀원과 플랫폼, 하단에는 아이보리색 보유 캐릭터 바를 둔다. 비율은 기기별로 조정하며 픽셀 고정값으로 잠그지 않는다.

왼쪽 패널에는 뒤로가기, 편성 제목, 팀 01·02·03 선택, 팀 이름 수정, 팀 전투력을 표시한다. 중앙 팀원들은 일렬로 같은 자세를 취하지 않고 각각 돌아보기·장갑 점검·가방 들기·휴대전화 보기 등의 개별 동작을 가진다.

각 팀원 아래에는 이름·레벨·역할 아이콘과 상세 또는 교체 진입 표시를 둔다. 바닥의 01·02·03·04 표식은 슬롯 위치를 나타낸다. 선택된 슬롯은 청록색 바닥과 테두리로 강조한다. 리더는 별도 배지로 구분하며 선택 상태와 혼동하지 않는다.

하단에는 보유 캐릭터 썸네일 목록, 선택 표시, 수평 스크롤, 자동 편성·초기화·편성 저장을 둔다. 저장 버튼은 노란색으로 가장 강조한다. 실제 사용 가능한 캐릭터와 미보유 캐릭터를 혼동하게 만드는 자물쇠 표시는 데이터 의미를 명확히 정의한 경우에만 사용한다.

### 조작 규칙 초안

- 중앙 슬롯을 누르면 교체할 슬롯이 선택되고, 하단에서 캐릭터를 선택하면 해당 슬롯을 교체한다.
- 이미 팀에 있는 캐릭터를 선택하면 기본적으로 두 슬롯의 위치를 교환한다. 동일 캐릭터 중복 배치는 기본 금지하되 전투 규칙 변경에 대응할 수 있게 한다.
- 캐릭터 상세는 별도 정보 버튼으로 연다. 교체 동작과 상세 진입이 겹치지 않게 한다.
- 팀 프리셋은 독립적으로 저장한다. 팀 이름 변경도 해당 팀에만 반영한다.
- 편집 중에는 저장 전 변경 표시를 제공한다. 저장하지 않고 팀 변경·뒤로가기를 하면 저장 또는 변경 취소를 선택하게 한다.
- 초기화는 현재 편집본을 마지막 저장 상태로 되돌리는 뜻으로 사용한다. 전원 해제를 원한다면 버튼명을 따로 만든다.
- 자동 편성은 UI 검증 단계에서만 전투력 기준 등 명시된 임시 알고리즘을 사용한다. 역할·속성 시너지가 확정되기 전에는 최적 팀이라고 표시하지 않는다.
- 빈 슬롯은 자리에 인물을 그리지 않고 번호와 추가 버튼을 표시한다. 허용 최소 인원은 전투 규칙 설정에서 관리한다.
- 편성 저장은 편성을 저장하는 동작이다. 저장만으로 전투에 진입하지 않는다. 출전 준비 화면에서는 별도의 출전 버튼을 둔다.

### 편성 애니메이션 초안

진입 시 플랫폼 배경이 먼저 보이고 팀원과 UI가 짧게 정착한다. 슬롯 선택 시 해당 캐릭터가 시선을 돌리거나 자세를 바꾸며 바닥 표식이 반응한다. 교체 시 기존 캐릭터가 빠지고 새 캐릭터가 같은 슬롯의 지정 위치로 들어온다.

슬롯별 서 있는 위치, 캐릭터 크기, 얼굴 안전 영역을 정의한다. 키와 의상이 다른 캐릭터가 들어와도 이름표·다른 인물을 심하게 가리지 않아야 한다. 전원에게 같은 대기 동작을 동기화하지 않는다.

매번 4명 전체를 퇴장시키는 긴 연출은 피한다. 빠른 교체와 연타에서는 이전 전환을 정리하고 최종 선택을 반영해야 하며, 저장 데이터와 화면 인물이 달라지는 상태를 허용하지 않는다.

## 8 캐릭터와 성장

캐릭터 목록은 보유 여부, 레벨, 역할, 속성 등 확정된 데이터 기준으로 정렬·필터링한다. 캐릭터 상세는 기본 정보·스킬·장비·성장 탭을 중심으로 설계한다. 돌파·각성·호감도 등은 후보이며 확정 시스템처럼 강제 추가하지 않는다.

상세 화면에서는 탭별로 카메라와 포즈를 바꿀 수 있도록 상태를 나눈다. 예를 들어 기본 정보는 상반신, 스킬은 능력 시연 자세, 장비는 무기와 소품이 잘 보이는 구도다. 구체적 모션은 캐릭터별 에셋에 따라 달라진다.

레벨업과 장비 변경은 적용 전후 수치, 필요한 재료, 부족 재료를 명확히 표시한다. 임시 시너지나 전투력 수식을 UI 코드에 하드코딩하지 않는다. 이름·속성·희귀도도 데이터로 관리한다.

가방은 장비·소모품·재료 등의 분류와 상세 패널을 제공한다. 수량, 사용, 장착, 잠금 등은 실제 지원하는 행동만 노출한다. 코스튬과 로비 설정은 성장과 혼동하지 않도록 구분한다.

## 9 영입과 상점

영입과 상점은 로비에서 각각 접근한다. 영입은 캐릭터 획득, 상점은 상품·재화 구매와 교환이 중심이다.

영입에는 한정·상시 구분, 픽업 선택, 캐릭터 소개, 기간, 보유 재화, 1회·10회 버튼, 상세 정보, 확률 정보, 기록, 교환소 연결을 설계한다. 1회·10회는 기존 시안 기준의 초기 조작안이다. 구체적인 비용·확률·천장·포인트·중복 변환은 아직 미정이다.

4개 영입 후보는 지하철 등장, 거리 전광판, 능력자 파일, 스카우트 방송이다. 최종 영입 디자인을 편성 시안 선택으로 대체 확정하지 않는다. 초기 흐름 검증이 필요하면 공통 구조를 구현하고 스킨을 교체할 수 있게 한다.

영입 결과는 신규 캐릭터 등장 → 개별 정보 → 전체 결과 → 닫기 또는 재영입으로 연결한다. 애니메이션 스킵은 결과 확정 자체를 다시 실행하지 않는다. 결과를 다시 열어도 같은 거래 결과를 보여줘야 한다.

상점은 추천, 패키지, 재화, 교환소 구성을 초안으로 둔다. 상품 카드에는 구성, 가격 또는 교환 비용, 구매 가능 횟수, 종료 기간을 표시한다. 4개 기존 상점 시안은 후보이며 상품과 가격도 임시다.

프로토타입에서는 테스트 재화로 구매·영입을 검증할 수 있다. 실제 운영에서는 서버가 잔액 차감·결과·지급을 하나의 거래로 처리하며, 재시도로 중복 차감 또는 중복 지급되지 않게 한다. 실결제 연동은 플랫폼·상품·영수증 검증을 결정한 후 수행한다.

## 10 여섯 콘텐츠의 화면 범위

| 콘텐츠 초안 | 필요한 메뉴 | 아직 결정할 규칙 |
| --- | --- | --- |
| 스토리 | 챕터 목록, 스테이지, 적·보상 정보, 출전 준비 | 스토리 분량, 해금, 전투 방식 |
| 도시 탐색 | 도시 지도, 구역, 사건 목록, 진입 정보 | 맵 생성, 이동, 반복성, 탐색 시간 |
| 현상수배 | 대상 게시판, 상세, 난이도, 보상 | 갱신 주기, 도전 횟수, 대상 생성 |
| 훈련 | 훈련 종류, 난이도, 재료 보상 | 소모 자원, 반복·소탕, 입장 제한 |
| 아레나 | 등급, 상대, 방어 편성, 전적 | 실시간 또는 비동기, 매칭, 시즌 |
| 레이드 | 보스, 난이도, 참가, 결과와 보상 | 솔로 또는 협동, 인원, 시즌 |

이 여섯 화면을 누르면 실제 상세 또는 준비 화면으로 이동해야 한다. 전투가 미구현이면 테스트 전투임을 개발 문서에서 명시하고, 완성된 콘텐츠라고 보고하지 않는다. 전투 방향 확정 전에 실시간 매칭·협동 서버를 임의 구축하지 않는다.

공통 출전 준비에는 선택한 팀, 적 정보, 필요 자원, 보상을 표시한다. 전투 화면에는 체력·스킬·목표·일시정지, 결과에는 승패·보상·재도전·로비 복귀가 필요하다. 세부 HUD는 전투 규칙을 정한 뒤 확정한다.

## 11 운영 메뉴와 공통 상태

필요한 보조 화면은 미션·업적, 이벤트 목록·상세, 출석, 우편함, 공지, 프로필, 설정이다. 로비의 메시지 메뉴를 유지한다면 캐릭터 대화 목록과 대화 화면을 별도 설계한다. 실시간 유저 채팅으로 확대 해석하지 않는다.

설정에는 BGM·효과음·음성 음량, 그래픽 품질, 연출 감소, 계정 관련 항목을 둔다. 계정 항목은 실제 구현된 기능만 연결한다.

모든 화면은 초기 로딩, 데이터 없음, 요청 실패, 재시도, 잠금, 선택됨, 보상 수령 완료 상태를 정의한다. 재화 부족은 필요한 양과 현재 양을 보여준다. 보상 받기 버튼을 연속 눌러도 한 번만 지급되어야 한다. 알림 점은 실제 미확인 또는 수령 가능 상태와 일치해야 한다.

## 12 모션과 사운드 구현 기준

속도감은 짧고 명확한 가속, 전환 방향, 캐릭터 동작과 UI의 타이밍 일치로 만든다. 화면 흔들기와 번쩍임을 과도하게 반복하지 않는다. 큰 연출이 있어도 입력 반응은 즉시 제공한다.

아래 시간은 개발 초기 조정값이며 사용자 확정값이 아니다.

| 동작 | 초기 목표 |
| --- | --- |
| 버튼 눌림 피드백 | 약 0.08~0.15초 |
| 탭·필터 전환 | 약 0.15~0.3초 |
| 일반 메뉴 전환 | 약 0.3~0.6초 |
| 팀원 교체 | 약 0.3~0.7초 |
| 특별한 첫 등장 | 약 1~2.5초 |
| 오프닝 | 약 15초 |

캐릭터 등장, 대기, 선택, 교체, 퇴장 상태를 구분한다. 화면 이동을 취소하거나 반복해도 모션이 중첩되지 않게 한다. 숨겨진 화면의 영상·음성·애니메이션은 중지한다.

BGM, 메뉴 클릭, 선택, 저장, 영입 결과의 소리를 구분한다. 여러 캐릭터 음성이 동시에 겹치지 않도록 제어한다. 감각적인 그래픽 스타일을 참고하되 기존 게임 음악을 복제하지 않는다.

## 13 에셋과 구현 구조

캐릭터별 최소 에셋은 초상화, 로비 등장·대기, 편성 슬롯용 전신 또는 반신, 편성 대기·선택, 상세 탭별 포즈다. 영입용 키비주얼과 등장 연출은 별도 에셋으로 둔다. 배경은 로비·플랫폼·영입·상점·지도별로 구분한다.

2D 일러스트, Live2D·Spine 등 리깅, 동영상, 3D 중 어떤 방법을 사용할지는 기존 에셋과 목표 기기 성능에 따라 결정한다. 시안만으로 3D 캐릭터가 준비되어 있다고 가정하지 않는다. 정적 에셋으로 시작하는 경우 무엇이 임시인지 명확히 기록한다.

캐릭터 설정에는 portrait, lobby, formation, detail, recruitment 에셋 참조와 슬롯별 위치 보정값을 둔다. UI 이름표와 버튼은 이미지에 굽지 않고 실제 텍스트·컴포넌트로 구현한다.

공통 컴포넌트는 버튼, 탭, 재화 표시, 캐릭터 썸네일, 역할 아이콘, 알림, 상세 패널, 확인 팝업, 로딩·오류 표시를 포함한다. 공통 기능은 재사용하되 모든 화면을 같은 카드 레이아웃으로 통일하지 않는다.

서버 연동에서는 요청 중복 방지, 실패 후 상태 조회, 원자적 차감·지급, 기간과 한도 검증이 필요하다. 클라이언트가 보낸 희귀도나 보상값을 그대로 신뢰하지 않는다. 오프라인 데모의 랜덤 결과를 운영 가챠로 사용하지 않는다.

## 15 클로드 작업 순서와 검수

1. 기존 저장소·엔진·실행법·에셋을 확인한다. 기존 코드가 있으면 활용하고 무관한 파일을 수정하지 않는다. 새 프로젝트라면 목표 플랫폼과 전투 요구에 맞는 기술 선택안을 먼저 제시한다.
2. 화면 이동과 상태 저장 구조를 만든다. 로비 → 편성 → 캐릭터 교체 → 저장 → 로비 → 편성 재진입이 실제로 동작하는지 확인한다.
3. 채택한 플랫폼 편성창을 우선 구현한다. 화면 배치와 조작을 맞춘 뒤 캐릭터별 동작을 적용한다.
4. 대표 캐릭터 1명 로비, 캐릭터 목록·상세, 영입·결과, 상점·가방을 연결한다. 확정되지 않은 시스템은 분리된 샘플 데이터로 둔다.
5. 오프닝과 메뉴 전환, 사운드, 에셋 로딩·해제를 적용한다. 정지 이미지와 실제 구현된 애니메이션을 구분해서 보고한다.
6. 여섯 콘텐츠의 진입·상세·준비 화면을 연결한다. 전투 구현은 결정된 전투 규칙에 맞춰 별도 범위를 산정한다.
7. 계정·저장·서버·실결제를 결정하고 운영 경로를 구현한다. 서버 미연동 상태를 출시 완료로 표현하지 않는다.

각 단계는 실행 가능한 결과를 남기는 제작 순서이며, 사용자 경험을 단순 와이어프레임 수준으로 낮추라는 뜻이 아니다.

검수 항목:
- 플랫폼 시안의 왼쪽 팀 패널, 중앙 팀원, 바닥 슬롯, 하단 목록, 노란 저장 버튼이 유지된다.
- 슬롯 교체·팀 저장·프리셋 변경·재시작 복원이 일관되게 동작한다.
- 빠른 연타에도 최종 선택과 저장 결과가 일치한다.
- 대표 로비 캐릭터와 팀 리더가 독립적으로 유지된다.
- 6개 콘텐츠 및 관리 메뉴에 막힌 링크가 없다.
- 영입과 상점 테스트에서 재화·아이템 변경이 한 번만 발생한다.
- 오프닝은 약 15초이며 한글이 없고, 타이틀에서 입력을 기다린다.
- 서로 다른 화면에 맞는 장면·구도·전환이 구현되어 있다.
- 노치·안전 영역과 긴 화면비에서 얼굴·이름·주요 버튼이 잘리지 않는다.
- 글자 가독성, 색상 외 선택 표시, 연출 감소 설정을 확인한다.
- 목표 기기 확정 후 성능을 측정한다. 60fps는 초기 목표이며 아직 검증된 성능 수치가 아니다.
