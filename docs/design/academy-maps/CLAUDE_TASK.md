# 클로드에게 전달할 게임 적용 요청

첨부 ZIP의 배경을 어빌리티킹덤 스토리 모드에 적용해주세요. 기획 설명으로 끝내지 말고 저장소를 확인한 뒤 실제로 탐색 가능한 상태까지 구현해주세요.

먼저 `README.md`, `MAP_PLAN.md`, `map_manifest.json`을 읽고 저장소의 AGENTS.md 등 작업 지침과 기존 스토리 모드·렌더러·이동·충돌·카메라·맵 전환·캐릭터 에셋 구조를 확인하세요. 기존 엔진이나 프레임워크를 추측해 새 프로젝트를 만들지 마세요.

## 필수 적용 범위

1. 8장 이미지를 **정문 1개 맵 + 수업동 연결 복도 1개 맵**으로 적용하세요. 각 맵의 4장은 겹치는 카메라 화면이며 별도 방이 아닙니다.
2. `map_manifest.json` 좌표로 배경을 복원하세요. `reconstruct_maps.py`를 실행하면 픽셀 겹침을 검사한 뒤 맵당 1672×941 PNG를 생성합니다. Python/Pillow가 없으면 기존 프로젝트 도구로 동일하게 합성하세요. 네 이미지를 단순히 2×2로 붙이거나 블렌딩하지 마세요.
3. 기존 세렌 캐릭터와 애니메이션·입력 방식을 사용해 이동시키세요. 에셋이 없다면 저장소에서 실제 가능한 대체 확인 방식을 명시하고, 임의 캐릭터를 세렌이라고 보고하지 마세요.
4. 플레이어 추적 카메라, 경계 제한, 편집 가능한 보행·충돌 영역, 출입구 전환을 구현하세요. 화면을 확대해 보는 방식이며 배경 전체를 한 화면에 맞추지 마세요.
5. 기둥·화단 등 전경 가림이 필요한 곳은 기존 마스크·레이어 기능을 활용하세요. 단일 배경의 한계를 숨기지 말고, 분리가 안 된 곳은 진입 제한 등으로 처리한 범위를 보고하세요.
6. 두 맵을 확인할 개발용 진입 방법을 제공하세요. 둘 사이 직접 전환은 테스트용 연결이며 확정된 챕터 동선이 아닙니다. 기존 스토리 진행과 데이터는 유지하세요.
7. 기존 HUD·대화·퀘스트 구조를 재사용하세요. 마나·포션·새 상점·신규 전투 시스템 등 요청하지 않은 기능은 추가하지 마세요.

## 구현 방식

- 작업 전 변경할 핵심 부분과 확인 방법을 짧게 정리하고 진행하세요.
- 기존 패턴에 맞춰 필요한 파일만 수정하고 의존성이나 엔진 교체는 피하세요.
- 충돌·포탈·스폰 좌표는 배경을 실제로 보며 지정하세요. manifest에는 이미지 배치만 들어 있습니다.
- 원본 이미지 8장은 보존하고 합성 배경은 파생 에셋으로 만드세요.
- 레포에 맞는 검사를 실행하고 가능하면 실제 실행 화면으로 카메라 이동과 충돌·전환을 확인하세요. 실행할 수 없는 항목은 검증 완료라고 쓰지 마세요.
- 배포·운영 반영은 이 요청의 범위가 아닙니다. 로컬 구현과 검증을 완료하세요.
